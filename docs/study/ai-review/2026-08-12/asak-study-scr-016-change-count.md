# SCR-016 메뉴 편집 변경사항 건수 학습

> 확인일: 2026-08-12
> 화면: SCR-016 관리자 메뉴 관리 편집 패널
> Figma Node: `134:12400` (`MenuEditPanel.jsx` 주석 기준)
> 범위: `ASAK-Admin/src/components/admin/menus/MenuEditPanel.jsx`

## 핵심 결론

하단의 `저장되지 않은 변경사항 n건`은 저장 전 원본(`baseline`)과 현재 입력값을 비교해 계산한다.
이제 전체 폼이 달라졌는지만 보는 것이 아니라, 바뀐 메뉴 필드·재료·옵션 그룹·태그를 각각 센다.

예를 들어 가격 변경 1건, 재료 추가 2건, 태그 삭제 1건이면 `4건`으로 표시된다.

## 화면의 역할과 데이터 흐름

```text
메뉴 목록에서 편집 선택
  -> MenuManagePage
  -> MenuEditPanel(menu)
  -> useEffect가 원본 데이터를 baseline에 저장
  -> 사용자가 form / ingredients / optionGroups / tags 변경
  -> useMemo의 dirtyCount 재계산
  -> 하단 문구에 n건 표시
  -> 저장 클릭
  -> onSave(payload)
```

`MenuEditPanel`은 변경 건수를 화면에 표시하는 역할이다. 실제 저장 요청과 저장 후 목록/상세 갱신은 부모인 `MenuManagePage`와 `useMenusQuery`가 담당한다.

## 어떤 것을 1건으로 세는가

| 대상 | 비교 기준 | 건수 |
| --- | --- | --- |
| 기본 정보 | 메뉴명, 카테고리, 가격, 설명, 판매 상태, 이미지 URL | 바뀐 필드마다 1건 |
| 재료 | `ingredientId`가 추가·삭제되거나 해당 재료의 속성이 변경됨 | 재료 1개당 1건 |
| 옵션 그룹 | `groupId` 또는 `optionGroupId`가 추가·삭제되거나 그룹 내용이 변경됨 | 그룹 1개당 1건 |
| 태그 | `code` 또는 `name` 기준으로 추가·삭제·내용 변경 | 태그 1개당 1건 |
| 영양·알레르기 | 이 패널에서는 자동 표시 값 | 건수에서 제외 |

한 재료의 수량과 역할을 함께 바꿔도 같은 재료이므로 2건이 아니라 1건이다.

## 핵심 코드 읽기

### 1. 원본 상태 만들기: `buildChangeSnapshot`

`baseline`에 비교 대상만 모아 저장한다. 화면에서 열고 닫는 모달 상태나 계산용 표시 값은 넣지 않는다.

```js
buildChangeSnapshot(form, ingredients, optionGroups, tags)
```

### 2. 행 단위 비교: `countChangedRows`

재료·옵션 그룹·태그는 배열이므로 ID로 원본과 현재 값을 연결한다.

- 원본에만 있으면 삭제 1건
- 현재에만 있으면 추가 1건
- 양쪽에 있지만 내용이 다르면 수정 1건

### 3. 최종 합계: `countChanges`

기본 정보는 필드별로 비교하고, 배열 데이터는 행 단위 결과를 더한다.

```text
변경 건수
= 변경된 기본 필드 수
+ 변경된 재료 수
+ 변경된 옵션 그룹 수
+ 변경된 태그 수
```

## 화면 상태 확인 범위

| 상태 | 확인 결과 |
| --- | --- |
| Default | 원본과 현재 값이 같으면 `변경사항 없음` 표시 |
| Changed | 하나 이상 다르면 `저장되지 않은 변경사항 n건` 표시 |
| Create | 새 메뉴에서는 `신규 메뉴 작성 중` 표시. 입력 후 건수가 생김 |
| Loading / Empty / Error | 이 패널 내부의 변경 건수 로직에서는 별도 상태가 없음. 메뉴 조회 상태는 부모 훅/페이지 범위 |
| Disabled | 영양정보의 재계산 버튼은 현재 `disabled`; 변경 건수와 연결되지 않음 |

## 확인된 사실과 미확인 범위

확인됨:

- `MenuEditPanel`이 `form`, `ingredients`, `optionGroups`, `tags`를 저장 payload에 포함한다.
- 하단 문구가 `dirtyCount`를 표시한다.
- 재료 추가 시 핵심 재료는 `canRemove: false`로 만들어진다.

미확인:

- 브라우저에서 재료/옵션/태그를 실제 조합해 표시 숫자를 수동 확인하는 작업은 아직 하지 않았다.
- `imageFile`은 저장 payload와 변경 건수 비교 대상에 포함되지 않는다. 이미지 업로드 API가 연결될 때 별도 결정이 필요하다.

## 직접 해볼 확인 순서

1. 기존 메뉴의 가격만 바꾸고 하단이 `1건`인지 확인한다.
2. 재료 두 개를 추가하고 태그 하나를 삭제해 `3건`이 더해지는지 확인한다.
3. 저장하지 않고 취소한 뒤 같은 메뉴를 다시 열어 `변경사항 없음`인지 확인한다.

## 연습 문제

1. 재료 하나를 삭제하고 같은 재료를 다시 추가하면 현재 비교 방식은 몇 건으로 보일까?
2. 옵션 그룹의 추천 옵션만 바꾸면 왜 옵션 항목이 아니라 옵션 그룹 1건으로 세는가?
3. `imageFile`을 변경 건수에 넣으려면 저장 API와 함께 어떤 값을 snapshot에 추가해야 할까?
